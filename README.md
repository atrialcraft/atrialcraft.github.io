# Atrial — сайт мастерской

Сайт [atrial.org](https://atrial.org): блог, инструкции к изделиям (на них ведут QR-коды), проекты и магазин мастерской Atrial.

Сайт **статический**: при сборке все страницы превращаются в готовые HTML-файлы (папка `out/`), которые можно положить на любой хостинг. Сервер, база данных и PHP не нужны.

Сделан на [Next.js](https://nextjs.org) с [MDX](https://mdxjs.com) (Markdown со вставками компонентов), [Tailwind CSS](https://tailwindcss.com) и [Motion](https://motion.dev). Основа — шаблон Брайана Руиса (b-r.io).

## Как добавить статью или инструкцию

Проще всего — в **Верстаке**, редакторе статей прямо на сайте. Его адрес не указан нигде на сайте, храните его в закладках. Верстак сам собирает файл статьи, сжимает фото и кнопкой «Опубликовать» отправляет всё в этот репозиторий. Через 2–3 минуты статья появляется на сайте.

Всё про оформление текста, фото, карусели, кнопки и про то, как подключить Верстак к GitHub, — в инструкции **[Как писать статьи для сайта](https://atrial.org/instructions/kak-pisat-stati)** (файл [src/app/instructions/kak-pisat-stati/page.mdx](src/app/instructions/kak-pisat-stati/page.mdx)).

Коротко, где лежат записи:

| Что | Папка | Адрес на сайте |
| --- | --- | --- |
| Статьи и видео | `src/app/blog/<адрес>/page.mdx` | `atrial.org/blog/<адрес>` |
| Инструкции | `src/app/instructions/<адрес>/page.mdx` | `atrial.org/instructions/<адрес>` |
| Статьи о проектах | `src/app/projects/<адрес>/page.mdx` | `atrial.org/projects/<адрес>` |

В Верстаке раздел выбирается полем «Тип»: статья и видео идут в блог, инструкция — в инструкции, проект — в проекты. Статьи о проектах обычно публикуются «только по прямой ссылке»: на них ведут карточки на странице «Проекты» ([src/app/projects/page.tsx](src/app/projects/page.tsx), поле `link`).

Адрес — это имя папки: латиницей, строчными, через дефис (`pechka-burzhujka`). **Не меняйте адреса инструкций**: на них ведут QR-коды на изделиях, и старый код перестанет работать.

## Как добавить товар

Товары пока добавляются вручную: создайте папку `src/app/market/<адрес>/`, положите туда `page.mdx` и фото `photo.jpg`. Удобнее всего скопировать папку существующего товара, например `zlynka`, и поменять в ней текст.

Начало файла `page.mdx`:

```js
import { ProductLayout } from '@/components/ProductLayout'
import { createProductMetadata } from '@/lib/products'
import photo from './photo.jpg'

export const product = {
  name: 'Наличник «Злынка»',
  description: 'Одно-два предложения: видно в карточке магазина и в превью ссылки',
  price: 2500, // в рублях; без цены будет «Цена по запросу»
  image: photo, // одно фото 3:4, см. «Какими делать фото»
  // или несколько: на странице товара будет карусель, в карточке магазина — первое фото
  // images: [photo1, photo2, photo3], // import photo1 from './01.jpg' и т. д.
  instruction: '/instructions/zlynka', // необязательно: кнопка «Инструкция»
  order: 20, // место в магазине: меньше — выше
  available: false, // необязательно: «Купить» неактивна, пока товар не в продаже
}

export const metadata = createProductMetadata(product)

export default ({ children }) => <ProductLayout product={product}>{children}</ProductLayout>
```

Ниже — подробное описание товара обычным Markdown, как в статьях.

Кнопка «Купить» предлагает написать в Telegram или ВКонтакте. Куда именно она ведёт, задаётся в [src/lib/site.ts](src/lib/site.ts) (`buyLinks`), одинаково для всех товаров.

## Какими делать фото

Сайт **не сжимает фото сам**: посетитель скачивает ровно тот файл, который лежит в репозитории. Верстак готовит фото статей автоматически, а всё остальное (товары, главная, «Обо мне») нужно подготовить вручную. Удобнее всего — в [Squoosh](https://squoosh.app): перетащите фото, выберите MozJPEG, задайте ширину и качество 80.

| Где фото | Пропорции | Размер | Вес |
| --- | --- | --- | --- |
| В статье | 3:2 или 4:3 горизонтально, вертикальные — не уже 4:5 | 1600 px по длинной стороне | 150–400 КБ |
| Карусель в статье | одинаковые у всех фото, по умолчанию 3:2 | 1600 px по длинной стороне | 150–400 КБ |
| Товар (одно фото или карусель `images`) | **3:4** вертикально, все фото одинаковые | 1200 × 1600 | 150–350 КБ |
| Лента на главной | вертикальное 4:5 | 800 × 1000 | до 200 КБ |
| Портрет «Обо мне» | вертикальное 4:5 | 1024 × 1280 | до 300 КБ |
| Обложка записи для соцсетей (`ogImage`) | 1.91:1 | 1200 × 630 | до 300 КБ |

Почему так:

- **Размер.** Колонка с текстом шириной около 670 px, а на телефонах и Retina-экранах нужно вдвое больше. 1600 px хватает с запасом. Снимок с телефона (4000+ px) обязательно уменьшайте — иначе страница будет грузиться долго.
- **Формат.** Фото — JPG с качеством 75–85 %. PNG — только для скриншотов и схем с мелким текстом. HEIC (формат iPhone) браузеры не показывают: конвертируйте или включите на iPhone **Настройки → Камера → Форматы → Наиболее совместимый**.
- **Товар — 3:4.** В карточке магазина и в карусели на странице товара фото показывается вертикально в пропорции 3:4, поэтому фото 3:4 видно целиком. Другие пропорции обрежутся по центру. В карточку идёт первое фото.
- **Лента на главной** обрезается до 4:5 по центру — у горизонтальных фото срежутся края.
- **Имена файлов** — латиницей, без пробелов: `photo.jpg`, `01.jpg`, `pechka.jpg`.

## Иконки сайта

Все иконки сделаны из одного знака-сквиркла, исходник — `src/images/favicon-mark.svg`. При замене логотипа нужно заменить все файлы из таблицы, сохранив имена и размеры.

| Файл | Размер | Где видно | Требования |
| --- | --- | --- | --- |
| `src/app/favicon.ico` | 16, 32 и 48 px в одном файле | вкладка браузера, закладки, поиск Яндекса и Google | можно с прозрачностью |
| `src/app/icon.svg` | вектор | вкладка в современных браузерах | можно с прозрачностью |
| `src/app/icon.png` | 512 × 512 | вкладка, если браузер не понимает SVG | можно с прозрачностью |
| `src/app/apple-icon.png` | 180 × 180 | iPhone и iPad: «На экран „Домой“» | **без прозрачности**: iOS сама скругляет углы, а прозрачное становится чёрным |
| `public/icons/icon-192.png` | 192 × 192 | Android: ярлык на главном экране | можно с прозрачностью |
| `public/icons/icon-512.png` | 512 × 512 | Android: экран загрузки; картинка для RSS | можно с прозрачностью |
| `public/icons/icon-maskable-512.png` | 512 × 512 | Android: ярлык в форме круга, капли и т. п. | без прозрачности, логотип в центральных 80 %: края Android обрезает |

Файлы из `src/app/` подключаются сами. Название и цвета для Android — в [src/app/manifest.ts](src/app/manifest.ts). Весь набор можно сделать из одной картинки на [realfavicongenerator.net](https://realfavicongenerator.net) и разложить по путям из таблицы.

## Как сайт попадает на atrial.org

Сайт живёт на **GitHub Pages** и обновляется сам:

1. Вы публикуете статью из Верстака, коммитите изменения на GitHub через сайт или делаете `git push` с компьютера.
2. GitHub Actions ([.github/workflows/deploy.yml](.github/workflows/deploy.yml)) собирает сайт и выкладывает его. Это занимает 2–3 минуты, ход сборки виден на вкладке **Actions** репозитория.
3. Если в статье ошибка, сборка падает с красным крестиком, а на сайте остаётся прошлая версия. Текст ошибки — в шаге **Build** этой сборки.

Кроме того, сайт пересобирается **каждый день в 06:00 по Москве**, чтобы обновить число просмотров статей.

Настройки, которые уже сделаны и которые не нужно трогать:

- **Settings → Pages → Source**: GitHub Actions. **Custom domain**: `atrial.org`, галочка **Enforce HTTPS**.
- **DNS домена** — в Cloudflare. Записи `A` для `atrial.org` указывают на адреса GitHub `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`, запись `CNAME` для `www` — на `atrialcraft.github.io`. **Прокси Cloudflare (оранжевое облако) выключен** — с ним сайт плохо открывается из России.
- ID аналитики — в **Settings → Secrets and variables → Actions** (см. «Настройки сборки»).

## Как разместить сайт на обычном хостинге по FTP

Если сайт нужно перенести с GitHub Pages на обычный хостинг для сайтов (Beget, Timeweb, REG.RU и т. п.), где есть только FTP или файловый менеджер, а консоли нет, — это возможно: хостингу нужно лишь отдавать готовые файлы.

### Шаг 1. Получить собранный сайт

**Способ А — скачать готовую сборку с GitHub, ничего не устанавливая.**

1. Откройте в репозитории вкладку **Actions** и выберите последнюю успешную сборку (зелёная галочка) **Deploy to GitHub Pages**.
2. Внизу страницы, в блоке **Artifacts**, скачайте `github-pages`. Скачается `github-pages.zip`.
3. Распакуйте его: внутри будет файл `artifact.tar` — распакуйте и его (на Mac — двойным щелчком, на Windows — 7-Zip или WinRAR). Получится папка с `index.html`, `_next`, `blog` и другими файлами — это и есть сайт.

Такая сборка сделана для адреса `https://atrial.org`. Если сайт будет открываться по другому адресу, используйте способ Б.

**Способ Б — собрать на своём компьютере.**

1. Установите [Node.js](https://nodejs.org) версии LTS (24 или новее) и [скачайте репозиторий](https://github.com/atrialcraft/atrialcraft.github.io/archive/refs/heads/main.zip) — или сделайте `git clone`.
2. Откройте Терминал в папке проекта (на Mac: правой кнопкой по папке → **Новый терминал по адресу папки**; на Windows: в адресной строке папки наберите `cmd` и Enter).
3. Выполните по очереди:

   ```bash
   npm ci
   NEXT_PUBLIC_SITE_URL=https://ваш-домен.ru npm run build
   ```

   На Windows вторая команда пишется так: `set NEXT_PUBLIC_SITE_URL=https://ваш-домен.ru && npm run build`. ID аналитики передаются так же, см. «Настройки сборки».

4. Готовый сайт появится в папке `out/`.

### Шаг 2. Загрузить на хостинг

1. Подключитесь к хостингу по FTP, например программой [FileZilla](https://filezilla-project.org) (данные для входа — в панели хостинга).
2. Откройте папку сайта на хостинге — обычно `public_html`, `www` или папка с именем домена. Удалите из неё старые файлы сайта (если это первая загрузка — заглушку хостинга, обычно `index.html` или `index.php`).
3. Загрузите в неё **содержимое** собранной папки — не саму папку, а то, что внутри: `index.html`, `_next`, `blog` и остальное.
4. Убедитесь, что загрузился скрытый файл **`.htaccess`**. Без него будут открываться только главная и страницы с `.html` на конце, а `/blog` и остальные адреса выдадут ошибку 404. FileZilla показывает скрытые файлы, если включить **Сервер → Принудительно показывать скрытые файлы**. На Mac в Finder скрытые файлы показываются сочетанием <kbd>Cmd</kbd> + <kbd>Shift</kbd> + <kbd>.</kbd>.
5. Откройте сайт и проверьте главную, `/blog` и любую статью.

### Что нужно от хостинга

- **Apache с поддержкой `.htaccess`** — так устроено большинство обычных хостингов. Файл [public/.htaccess](public/.htaccess) научит его открывать `/blog/pechka-burzhujka` как `blog/pechka-burzhujka.html` и показывать фирменную страницу 404.
- Если на хостинге **только nginx** и `.htaccess` не работает, напишите в поддержку: «Для статического сайта нужно `try_files $uri $uri.html $uri/ =404;` и `error_page 404 /404.html;`».
- Домен и HTTPS подключаются в панели хостинга. Если меняете хостинг для `atrial.org`, перенаправьте DNS-записи домена в Cloudflare на адрес нового хостинга, а на GitHub в **Settings → Pages** уберите свой домен.

### Как обновлять сайт на таком хостинге

Каждое изменение — новая статья, товар, правка текста — требует заново получить сборку (шаг 1) и заново загрузить её (шаг 2), заменив все файлы. Старую папку `_next` лучше удалять целиком: в ней копятся файлы прошлых версий.

Учтите:

- **Верстак публикует статьи в репозиторий GitHub**, а не на хостинг. После публикации дождитесь, пока на GitHub закончится сборка, и перенесите её на хостинг.
- **Число просмотров** обновляется только при сборке на GitHub, то есть в сборке со способа А оно свежее, а со способа Б — такое, какое лежит в `src/data/views.json`.

## Как запустить сайт на своём компьютере

Это нужно, только если вы меняете дизайн или код сайта и хотите сразу видеть результат. Для статей это не нужно — для них есть Верстак.

1. Установите [Node.js](https://nodejs.org) LTS и скачайте репозиторий (см. способ Б выше).
2. В Терминале в папке проекта: `npm ci` — один раз, установит всё нужное в папку `node_modules`.
3. Скопируйте файл `.env.example` в `.env.local` — там адрес сайта и пустые ID аналитики. Аналитику на своём компьютере лучше оставить выключенной, чтобы не портить статистику.
4. Запустите один из режимов:

| Команда | Что делает |
| --- | --- |
| `npm run dev` | **Режим разработки.** Сайт открывается на [localhost:3000](http://localhost:3000) и сразу обновляется при каждом сохранении файла. Работает только пока открыт Терминал; это не настоящий сайт, а черновой просмотр для правок. |
| `npm run build` | Собирает готовый сайт в папку `out/` — то же, что делает GitHub. Если в коде или статье ошибка, сборка остановится и покажет её. |
| `npm run preview` | Открывает собранную папку `out/` на [localhost:3000](http://localhost:3000) — так сайт будет выглядеть на хостинге. Сначала нужна `npm run build`. |
| `npm run lint` | Проверяет код на ошибки и подозрительные места. |

Остановить `dev` или `preview` — <kbd>Ctrl</kbd> + <kbd>C</kbd> в Терминале.

## Настройки сборки

Сборка берёт настройки из переменных окружения. На GitHub они заданы в **Settings → Secrets and variables → Actions**, на своём компьютере — в файле `.env.local` или прямо в команде сборки.

| Переменная при сборке | На GitHub | Что это |
| --- | --- | --- |
| `NEXT_PUBLIC_SITE_URL` | задан в workflow | Адрес сайта: нужен для ссылок в превью соцсетей, `sitemap.xml` и RSS. Без него там будет `localhost:3000` |
| `NEXT_PUBLIC_YANDEX_METRIKA_ID` | переменная `YANDEX_METRIKA_ID` | Номер счётчика Яндекс Метрики. Пусто — Метрика выключена |
| `NEXT_PUBLIC_GA_ID` | переменная `GA_ID` | ID Google Analytics 4, вида `G-…`. Пусто — выключено |
| `NEXT_PUBLIC_TELEGRAM_PIXEL_ID` | переменная `TELEGRAM_PIXEL_ID` | ID пикселя Telegram Ads. Пусто — выключено |
| `METRIKA_TOKEN` | секрет `METRIKA_TOKEN` | OAuth-токен Яндекса с правом `metrika:read` для числа просмотров, см. ниже |

На странице Верстака аналитика не загружается никогда.

### Число просмотров статей

Перед каждой сборкой на GitHub скрипт [scripts/fetch-views.mjs](scripts/fetch-views.mjs) забирает из Яндекс Метрики число просмотров каждой страницы в `src/data/views.json`, и сайт показывает его рядом с датой статьи. Для этого нужны секрет `METRIKA_TOKEN` и переменная `YANDEX_METRIKA_ID`. Если токена нет или Метрика не ответила, сайт всё равно собирается — просто без новых цифр.

Получить токен: создайте приложение на [oauth.yandex.ru](https://oauth.yandex.ru) с доступом «Яндекс Метрика → Получение статистики», затем откройте `https://oauth.yandex.ru/authorize?response_type=token&client_id=<ID приложения>` и скопируйте токен из адресной строки. Токен никому не пересылайте — только в секрет репозитория.
