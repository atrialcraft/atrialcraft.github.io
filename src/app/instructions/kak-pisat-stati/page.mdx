Каждая запись на сайте — это папка с файлом `page.mdx`. Внутри обычный текст в формате Markdown, а в начале — короткая «шапка» с названием, датой и типом записи. Фото лежат в той же папке.

Проще всего писать в **Верстаке** — редакторе статей прямо на сайте, по секретному адресу. Он сам собирает шапку, сжимает фото и публикует статью.

## Верстак

1. **Поля сверху** — тип записи (статья, видео, инструкция), заголовок, описание, дата и адрес. Адрес придумывается сам из заголовка, но его можно поправить. Для видео появится поле для кода ролика YouTube. Галочки «Только по прямой ссылке» и «Показывать на главной» — те же `visibility` и `showOnHome`, что в шапке.
2. **Фото** — кнопка «+ Добавить фото» или перетаскивание прямо в текст. Верстак уменьшит их до 1600 пикселей, сохранит в WebP, назовёт `01.webp`, `02.webp`… и вставит в текст тегом `Photo`. Под каждым фото видно, где оно уже стоит: «в тексте», «в карусели» или «не вставлено».
3. **Карусель** — отметьте у фото галочки «в карусель» в нужном порядке и нажмите «Карусель из выбранных».
4. **Панель над текстом** — кнопки для всего оформления из этой шпаргалки: жирный, курсив, заголовки, списки, цитата, ссылка, кнопка-ссылка, код, таблица, спойлер, клавиша, выравнивание, разделитель. Кнопка оборачивает выделенный текст, а если ничего не выделено — вставляет заготовку.
5. **Вкладки** — «Текст» для письма, «Превью» показывает статью так, как она будет выглядеть на сайте (и подсвечивает ошибки), «Код» — готовый `page.mdx`.
6. **Готово** — «Опубликовать» отправляет статью прямо на сайт (нужен токен GitHub, см. ниже). Без токена — «Скачать ZIP»: папка со статьёй и фото, которую можно опубликовать вручную. «Новая статья» очищает Верстак.

Черновик и фото хранятся только в этом браузере: закрыть вкладку можно, а вот на другом устройстве их не будет.

| Сочетание клавиш | Что делает |
| --- | --- |
| <kbd>Cmd</kbd> + <kbd>B</kbd> | жирный |
| <kbd>Cmd</kbd> + <kbd>I</kbd> | курсив |
| <kbd>Cmd</kbd> + <kbd>U</kbd> | подчёркнутый |
| <kbd>Cmd</kbd> + <kbd>Shift</kbd> + <kbd>X</kbd> | зачёркнутый |
| <kbd>Cmd</kbd> + <kbd>K</kbd> | ссылка |
| <kbd>Cmd</kbd> + <kbd>E</kbd> | код в строке |

На Windows вместо <kbd>Cmd</kbd> — <kbd>Ctrl</kbd>.

## Как опубликовать

**Из Верстака, одной кнопкой.** Нажмите «Опубликовать» — Верстак сам проверит текст на ошибки, отправит статью и фото в репозиторий одним коммитом, и через 2–3 минуты запись появится на сайте. Если запись с таким адресом уже есть, Верстак спросит, заменить ли её. Для этого один раз нужно подключить GitHub токеном.

<details>
  <summary>Как создать токен GitHub</summary>

1. На github.com нажмите на аватар справа вверху → **Settings** → в самом низу меню слева **Developer settings** → **Personal access tokens** → **Fine-grained tokens** → **Generate new token**.
2. **Token name** — например, «Верстак Atrial». **Resource owner** — `atrialcraft`. **Expiration** — на год (потом создадите новый).
3. **Repository access** → **Only select repositories** → выберите `atrialcraft.github.io`.
4. **Permissions** → **Repository permissions** → **Contents** → **Read and write**. Больше ничего не нужно.
5. Нажмите **Generate token** и скопируйте его (начинается с `github_pat_`). GitHub показывает токен один раз.
6. Если токен «ждёт одобрения» — организация просит подтвердить доступ: откройте настройки организации `atrialcraft` → **Personal access tokens** → **Pending requests** и одобрите.
7. В Верстаке нажмите **Подключить GitHub**, вставьте токен и **Сохранить**.

Токен хранится только в этом браузере и даёт доступ только к файлам этого репозитория. Не пересылайте его никому. Если потеряли устройство — удалите токен на той же странице GitHub, и он перестанет работать.

</details>

Если вы работаете с репозиторием и на компьютере, после публикации из Верстака сделайте там `git pull`, чтобы забрать новую статью.

**Из Верстака, вручную.** Скачайте ZIP, распакуйте папку в нужный раздел и опубликуйте одним из способов ниже.

**С компьютера.** Создайте папку, положите в неё `page.mdx` и фото, затем закоммитьте и сделайте `git push`. Через пару минут запись появится на сайте.

**Прямо на GitHub, без программ.** В репозитории нажмите **Add file → Create new file** и впишите путь, например `src/app/blog/moya-statya/page.mdx` — папка создастся сама. Фото добавляются через **Add file → Upload files** в ту же папку. После сохранения (**Commit changes**) сайт пересоберётся сам.

Проще всего начать с копии существующей записи: скопируйте её папку, переименуйте и замените текст.

## Шапка записи

```js title="page.mdx"
import { PostLayout } from '@/components/PostLayout'
import { createPostMetadata } from '@/lib/posts'
import photo01 from './01.webp'

export const post = {
  type: 'article', // 'article' — статья, 'video' — видео, 'instruction' — инструкция
  author: 'Daniil Kolbunov',
  date: '2026-10-18', // ГГГГ-ММ-ДД, по дате записи сортируются
  title: 'Печка-буржуйка из листовой стали',
  description: 'Одно-два предложения: видно в списке записей и в превью ссылки',
  youtubeId: 'dQw4w9WgXcQ', // только для type: 'video' — код из ссылки на YouTube
  visibility: 'public', // 'unlisted' — открывается только по прямой ссылке
  showOnHome: true, // false — не показывать в блоке «Блог» на главной
}

export const metadata = createPostMetadata(post)

export default ({ children }) => <PostLayout post={post}>{children}</PostLayout>

Дальше идёт сам текст статьи.
```

- **Заголовок и описание** в текст повторять не нужно — сайт выводит их сам вместе с датой.
- **`visibility: 'unlisted'`** — записи нет ни в списках, ни в RSS, поисковикам запрещено её индексировать, но по прямой ссылке она открывается. Так удобно готовить черновик или инструкцию только для QR-кода. Эта шпаргалка как раз такая.
- **Видео с YouTube** в России открывается плохо. Если ролик есть ещё и в Telegram, дайте в тексте ссылку и на пост в канале.

## Выделение текста

| Как написать | Как выглядит |
| --- | --- |
| `**жирный**` | **жирный** |
| `_курсив_` | _курсив_ |
| `**_жирный курсив_**` | **_жирный курсив_** |
| `~~зачёркнутый~~` | ~~зачёркнутый~~ |
| `<u>подчёркнутый</u>` | <u>подчёркнутый</u> |
| `<mark>маркер</mark>` | <mark>маркер</mark> |
| `` `код в строке` `` | `код в строке` |
| `H<sub>2</sub>O` | H<sub>2</sub>O |
| `м<sup>2</sup>` | м<sup>2</sup> |
| `<kbd>Cmd</kbd> + <kbd>C</kbd>` | <kbd>Cmd</kbd> + <kbd>C</kbd> |
| `\*не курсив\*` | \*не курсив\* |
| `10&nbsp;мм` | 10&nbsp;мм (не разорвётся при переносе) |

В Markdown нет отдельного подчёркивания, поэтому для него, маркера и индексов используются HTML-теги — внутри MDX они работают.

**Абзацы** разделяются пустой строкой. Чтобы перенести строку внутри абзаца, поставьте в её конце `<br />`.

**Экранирование.** Если нужно показать сам символ, который Markdown считает разметкой (`*`, `_`, `#`, `[`, `` ` ``), поставьте перед ним обратную косую черту: `\*`, `\_`, `\#`.

**Эмодзи** вставляются как обычный текст: 🔥 🪟 ⚙️.

## Выравнивание

По умолчанию текст выровнен по левому краю. Чтобы выровнять кусок по центру или вправо, оберните его в `<Align>` — пустые строки внутри обязательны, иначе Markdown в нём не сработает:

```md
<Align to="center">

**Текст по центру**

</Align>

<Align to="right">

Подпись справа

</Align>
```

<Align to="center">

**Текст по центру**

</Align>

<Align to="right">

Подпись справа

</Align>

Варианты: `left`, `center`, `right`. Внутрь можно положить что угодно — несколько абзацев, список, ссылку. В Верстаке это кнопки ⇤ ↔ ⇥.

## Цитата и разделитель

```md

---
```

> Буржуйка работает каждую зиму в режиме 24/7 уже три года.

```md
> Брянская область постепенно появляется на наличниковой карте страны.
>
> <cite>Иван Хафизов, Nalichniki.com</cite>
```

## Код

Блок кода оборачивается в три обратных апострофа, после них пишется язык — так включается подсветка:

````md
```cpp
void setup() {
  Keyboard.begin();
}
```
````

**Имя файла над блоком** — добавьте `title`:

````md
```cpp title="buttons.ino"
void loop() {}
```
````

```cpp title="buttons.ino"
void loop() {}
```

**Номера строк** — `showLineNumbers`, **выделить строки** — номера в фигурных скобках:

````md
```cpp {2} showLineNumbers
void setup() {
  Keyboard.begin(); // эта строка подсвечена
}
```
````

```cpp {2} showLineNumbers
void setup() {
  Keyboard.begin(); // эта строка подсвечена
}
```

**Изменения в коде** — язык `diff`, строки с `+` подсвечиваются зелёным, с `-` красным:

````md
```diff
- delay(1000);
+ delay(500);
```
````

```diff
- delay(1000);
+ delay(500);
```

**Код в строке, внутри которого есть обратный апостроф,** оборачивается в двойные: ``` `` код с ` внутри `` ```.

Частые языки: `js`, `ts`, `python`, `cpp` (Arduino), `bash`, `json`, `yaml`, `css`, `html`, `md`, `diff`. Для текста без подсветки — `text`. У каждого блока кода есть кнопка «Скопировать».

## Фото

Фото кладётся в папку записи, подключается в шапке через `import` и вставляется тегом `Photo` — в нём же задаются подпись, размер и положение. Верстак делает импорт и вставку сам, остаётся вписать `alt` и подпись:

```md
import photo01 from './01.webp'

<Photo src={photo01} alt="Сварка корпуса печи" caption="Подпись под фото" />
```

| Настройка | Значения | Что делает |
| --- | --- | --- |
| `size` | `full` (по умолчанию), `medium`, `small` | вся ширина колонки, три четверти, половина |
| `align` | `center` (по умолчанию), `left`, `right` | где стоит фото, если оно меньше колонки |
| `wrap` | просто написать `wrap` | текст обтекает фото сбоку — для `small` и `medium` с `left` или `right` |
| `caption` | любой текст | подпись под фото, можно не писать |

На телефоне любое фото растягивается на всю ширину — иначе маленькое было бы не разглядеть. Кнопки выравнивания ⇤ ↔ ⇥ в Верстаке меняют `align` у фото, если курсор стоит на строке с ним.

**Маленькое по центру:**

```md
<Photo src={photo01} alt="…" size="small" />
```

<Photo src={demoPhoto} alt="Сварка корпуса печи" size="small" caption="size=&quot;small&quot;" />

**Среднее справа:**

```md
<Photo src={photo01} alt="…" size="medium" align="right" />
```

<Photo src={demoPhoto} alt="Сварка корпуса печи" size="medium" align="right" caption="size=&quot;medium&quot; align=&quot;right&quot;" />

**Маленькое слева, текст обтекает:**

```md
<Photo src={photo01} alt="…" size="small" align="left" wrap />

Текст статьи встанет справа от фото…
```

<Photo src={demoPhoto} alt="Сварка корпуса печи" size="small" align="left" wrap />

Так фото становится частью текста, как в журнале. Абзацы обтекают его справа, пока не закончится высота фото, а следующий заголовок раздела всегда начнётся уже под ним. На телефоне фото встанет над текстом во всю ширину. Подходит для небольших деталей, схем и портретов — для главных фото статьи лучше оставить полную ширину.

Старый способ — `<figure>` с тегом `Image` внутри — тоже работает:

```md
import photo01 from './01.webp'

<figure>
  <Image src={photo01} alt="Сварка корпуса печи" />
  <figcaption>Подпись под фото</figcaption>
</figure>
```

- **`alt`** — короткое описание того, что на фото. Его читают поисковики и экранные дикторы; без него фото как будто нет.
- **`figcaption`** можно не писать, если подпись не нужна.
- Файлы удобно называть по порядку: `01.webp`, `02.webp`…

**Фото с другого сайта** можно вставить обычной разметкой Markdown — но только по полной ссылке:

```md
![Описание фото](https://example.com/photo.jpg)
```

Свои фото так вставлять не надо: путь вида `./01.webp` в этой разметке не сработает. Для фото из папки записи — только `import` и `Photo`, как выше.

**Видео с YouTube внутри текста** (не как основное видео записи):

```md
<YouTubeEmbed id="dQw4w9WgXcQ" title="Как собрать наличник" />
```

**Карусель из нескольких фото** — листается свайпом на телефоне, стрелками и перетаскиванием на компьютере, точки под фото показывают, какое открыто. В Верстаке: отметьте фото галочками «в карусель» в нужном порядке и нажмите «Карусель из выбранных» — блок добавится сам. Вручную это выглядит так:

```md
import photo02 from './02.webp'
import photo03 from './03.webp'

<ImageCarousel
  images={[
    { src: photo02, alt: 'Вид спереди', caption: 'Подпись к первому фото' },
    { src: photo03, alt: 'Вид сбоку', caption: 'Подпись ко второму' },
  ]}
/>
```

Все фото в карусели обрезаются до одной пропорции — по умолчанию 3:2, чтобы карусель не прыгала по высоте. Другая пропорция задаётся так: `imageClassName="aspect-4/3"`, `"aspect-square"` или `"aspect-4/5"` для вертикальных. Общую подпись на всю карусель можно задать через `caption="…"`, а отдельное фото для тёмной темы — через `darkSrc: photo01dark`.

## Каким делать фото

Верстак сжимает фото сам: уменьшает до 1600 пикселей и сохраняет в WebP с качеством 82 %, так что всё ниже про размер, формат и вес он уже сделал. А вот соотношение сторон и обрезку выбираете вы.

Если кладёте фото в папку вручную, помните: сайт не сжимает картинки сам — посетитель скачивает ровно тот файл, который вы загрузили. Поэтому фото стоит подготовить заранее.

**Размер.** Колонка с текстом шириной около 670 пикселей, на телефонах и Retina-экранах нужно вдвое больше. Хватает **1600 пикселей по длинной стороне** — больше никто не увидит, а файл станет тяжелее. Снимок с телефона (4000+ пикселей) обязательно уменьшайте.

**Формат файла.**

- **WebP с качеством 75–85 %** — основной формат фото на сайте. На глаз не отличается от оригинала, а весит на 25–35 % меньше JPG. Поддерживается всеми современными браузерами.
- **JPG с качеством 75–85 %** — тоже подходит, если WebP сделать нечем. Старый Safari не умеет сохранять WebP, и Верстак в нём сохраняет фото в JPG.
- **PNG** — только для скриншотов, схем и картинок с мелким текстом. Фото в PNG весит в разы больше. Скриншот тоже можно перевести в WebP: у него есть прозрачность и режим без потерь качества.
- **HEIC** (формат iPhone по умолчанию) не подходит — сайт его не покажет. Верстак переведёт его в WebP, если браузер умеет его открывать (Safari умеет). Иначе конвертируйте сами или включите на iPhone **Настройки → Камера → Форматы → Наиболее совместимый**.

**Вес.** Ориентир — **150–400 КБ** на фото. Если больше 500 КБ, уменьшите размер или качество.

**Соотношение сторон.**

- **3:2 или 4:3 горизонтально** — лучший вариант для статьи: фото целиком помещается на экран и не заставляет листать.
- **4:5 вертикально** — максимум для вертикальных фото, как в Instagram.
- **9:16 внутри статьи не надо** — на компьютере такое фото займёт больше экрана в высоту. Если снимали вертикально на телефон, обрежьте до 4:5 или 3:4.
- **В карусели** все фото должны быть одного соотношения, иначе она будет прыгать по высоте.
- **Фото товара в магазине** — квадратное или горизонтальное: в карточке оно обрежется до квадрата по центру, на странице товара покажется целиком.

**Чем сжать.**

- **[Squoosh](https://squoosh.app)** — в браузере, бесплатно: перетащите фото, выберите WebP, поставьте ширину 1600 и качество 80. Сразу видно и вес, и разницу в качестве.
- **Просмотр на Mac** — **Инструменты → Настроить размер** (1600 по ширине), затем **Файл → Экспортировать** в JPEG с ползунком качества примерно на 80 %.

## Что ломает статью

MDX — это Markdown вперемешку с кодом, поэтому несколько символов в обычном тексте имеют особый смысл:

- **`{` и `}`** — пишите `\{` и `\}`, иначе сайт попытается выполнить содержимое как код.
- **`<`** — пишите `&lt;` (например, «напряжение &lt; 12 В»), иначе это будет понято как тег.
- **HTML-комментарии** `<!-- -->` не работают; оставить заметку, которая не видна на сайте, можно так: `{/* заметка */}`.

Внутри блоков кода всё это можно писать как есть. В Верстаке такие ошибки сразу видны на вкладке «Превью». Если после публикации запись не появилась — скорее всего, ошибка в файле: она видна во вкладке **Actions** на GitHub, в шаге сборки.
